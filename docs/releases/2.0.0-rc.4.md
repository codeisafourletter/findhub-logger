# 2.0.0-rc.4

Collector-focused candidate, based on stable main. This preserves the original Find Hub → private Sheet workflow and adds no new account, service, or UI.

Candidate only. This branch does not establish working Google authentication or enable the production schedule.

## Outcome

Configuration problems now produce named, actionable checks before launching Chrome. Collector failures report stable codes and recovery instructions without copying private Find Hub page text, URLs, remote response errors, or browser exception details into public GitHub logs. GitHub job summaries show the same safe recovery instructions.

## Changes

- `npm run doctor`: offline key, HTTPS receiver, shared-secret presence, and readable browser-state checks.
- `npm run doctor -- --json`: machine-readable output; exit 1 for invalid configuration and exit 0 when structural checks pass. Expired-cookie hints are warnings, not a claim that authentication works.
- Rolling encrypted state remains authoritative. Corrupt or wrong-key caches fail closed; a missing cache uses the bootstrap state.
- The collector uses the same preflight checks. It can use a valid rolling cache when no bootstrap value is supplied.
- Fixed failure codes cover authentication refresh, target/card lookup, coordinate extraction, Sheet writes, browser startup, and rolling-cache persistence.
- Existing successful collection JSON and the AES-256-GCM cache format remain compatible.

## Migration from 1.0.0

1. Install Node.js 22 and npm 10, then run `npm ci` in `cloud/`.
2. Keep the existing GitHub Actions secrets and cache configuration; no key rotation or data migration is required.
3. Replace log scraping of `COLLECTOR_DIAGNOSTIC` or raw exception messages with the JSON `code` field. Raw private-page diagnostics have intentionally been removed.
4. Run `npm run check`. When configuration is available through your normal secure environment, run `npm run doctor`.
5. For live acceptance, refresh the expired Google session with `finish-github-setup.ps1`, re-enable **Find Hub collector** if disabled, and verify one manual collection. Offline doctor/CI success is not live acceptance.

If the encryption key changes, reset `AUTH_STATE_EPOCH` as well as refreshing `AUTH_STATE_B64`; otherwise an old encrypted rolling cache will fail decryption.

## Limits and acceptance

The doctor does not contact Google, inspect repository secrets remotely, check the Actions schedule state, verify Chrome availability, or prove that the Sheet receiver is reachable. Empty/expired-cookie warnings may need human interpretation, particularly for session cookies. Sheet writes are not automatically retried: a lost response could mean the write succeeded, so blind retries risk duplicates.

Offline tests cover malformed configuration, expired-cookie warnings, cache precedence/corruption, CLI exit status, secret-free reports, and fixed failure codes. Real Google/Sheet integration remains unverified for this candidate.

## Version scope

The 2.0 major boundary is the intentional replacement of raw diagnostic log output with fixed, privacy-safe failure codes. Existing Sheet records, encrypted cache format, schedule and setup helper are unchanged. This rc.4 candidate supersedes earlier expanded UI candidates; it contains only collector diagnosis and failure-reporting improvements. Offline verification requires no Google account. Actual collection continues to require the existing Google sign-in and Sheet receiver.
